# War in Middle Earth (MSX, 1989) — a commented disassembly

*(También disponible [en castellano](README.es.md).)*

A complete, byte-for-byte reproducible disassembly of the MSX cassette of
**War in Middle Earth** (Melbourne House / Dro Soft, 1989, converted by Animagic
S.A.). The listing is generated from a real control-flow trace, not from a
linear disassembly, and `make verify` checks that reassembling it gives each
piece of the tape back exactly.

**The web version, with the pictures:** [antxiko.github.io/WarinMiddleEarth-MSX-disassembly](https://antxiko.github.io/WarinMiddleEarth-MSX-disassembly/)

## The tape is not here

This repository holds only the documentation work. To rebuild everything you
need your own copy of the tape, named `war.tsx` in the root, with this sha256:

    13c636328d1714d5e00419141ca1a7ac9c7a3a04d7ec2b26545212aab1d81208

## What is odd about this game

It is a **ZX Spectrum conversion** (Melbourne House, 1988) and they brought the
whole tape system across with it. The blocks are not MSX KCS blocks but Spectrum
ones (TZX `0x10`), with their `[flag][data][XOR]`, and the loader is a
reimplementation of the Spectrum ROM's LD-BYTES, written out by hand.

The game runs with **all four MSX pages in RAM and no BIOS**, in three blocks
that the boot code relocates. That is why it is traced over a 64 KB image and
split afterwards into three listings, each with the `org` where it really runs.

## Some of what turned up

- **The game is silent.** The Spectrum's beeper engine came across whole, at
  `0x6600`, and **nothing ever calls it**; the four places that ask for a sound
  effect all land on a bare `ret` at `0x65FF`; and of the MSX's PSG only the two
  joystick registers are ever written.
- **The map tiles are nine bytes long** — eight of drawing plus a ZX Spectrum
  attribute glued behind. The conversion did not redraw the artwork, it
  translates the colour on the fly.
- **`0x62FF` is not the cursor's artwork**: it is where the cursor saves the
  background it covers. The bytes on the tape there are whatever was under the
  cursor the day it was recorded.
- **The battle board is built on top of the menu's code**, and it is a
  draughtboard: the figures only ever move diagonally.
- **The friend-or-foe filter is an opcode switch**: the game writes `0xD0`
  (`ret nc`) or `0xD8` (`ret c`) into the middle of a routine to make it walk
  one side or the other.
- **The map travels compressed and gets recompressed before every battle**, to
  free exactly the RAM the battle buffers need.

They are all in [docs/FINDINGS.md](docs/FINDINGS.md), each with the address that
proves it.

## Usage

    make verify     # extract, trace, generate and check byte for byte
    make sanity     # trace coherence and the 100% budget
    make test       # the tests
    make imagenes   # redraws the PNGs from the tape
    make web        # regenerates the site

You need `pasmo`, `z80dasm` and `python3`.

## The pictures are not screenshots

Everything in `docs/imagenes/` is **drawn from the tape's own bytes**:
`tools/render_carga.py` rebuilds the loading screen the way the loader uploads
it, and `tools/render_graficos.py` develops the map tiles with their Spectrum
attributes, the battle sprites with their masks, and the font. If a range were
mislabelled, it would come out as noise.
